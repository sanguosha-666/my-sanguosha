# 大批次实现计划（超时托管 + 主公技 + bot.js 拆分 + D3/D4）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A1 响应超时托管（30s+倒数）、A2 断线重连验证、B2 四主公技、D2 bot-ai-bus.js 拆分、D3 AI_DEFAULT_MODEL 单源、D4 响应阶段 UI 回归、D1 真机验证。

**Architecture:** 批1 拆分+单源（减后续改动面）→ 批2 超时托管+重连 → 批3 主公技 → 批4 回归+真机。A1 用 pending `askedAt` 时间戳 + 任意客户端 setInterval 幂等提交保守动作；B2 主公技按 `p.role==='zhu'` 守卫；D2 只拆总线核心文件，加载顺序 bot-ai-bus 在 bot 前。

**Tech Stack:** 纯静态多文件 JS（无构建）；vm 沙箱测试；`?v=` cache-bust；Firebase 实时同步。

**Spec:** `docs/superpowers/specs/2026-08-03-big-batch-design.md`

## Global Constraints

- **分支**：只在 `wenwen_dev` 提交/推送（push 走 https 覆盖：`git -c url."https://github.com/".insteadOf= push https://github.com/zjc-taikutu/my-sanguosha.git wenwen_dev`）
- **无密钥回归红线**：各改动不改变无密钥本地行为（测试锁定）
- **隐藏信息**：不泄露手牌；主公技求助只暴露公开信息
- **`?v=`**：改动带 `?v=` 脚本时全部 13 处同步 +1（当前基线 298）
- **测试**：vm 加载真实源码；`let` 变量用 `vm.runInContext('x=...')`；函数声明可替换 spy
- **收尾**：progress-log-8 追加（当前 28.8KB <150KB）
- **执行顺序**：批1（D2→D3）→ 批2（A1→A2）→ 批3（B2）→ 批4（D4→D1），各自独立 commit
- **超时**：30s 固定（`RESPONSE_TIMEOUT_MS = 30000`），画面倒数
- **主公技**：激将/护驾/制霸 仅 `p.role==='zhu'` 且拥有技能；妄尊袁术对主公触发

**Files:**
- Modify: `game.js`（pending askedAt 打戳 + normalize 兜底）、`bot.js` 或 `bot-ai-bus.js`（setInterval 检测器 + 保守提交）、`render.js`（倒计时显示）

**Interfaces:**
- Produces: `RESPONSE_TIMEOUT_MS = 30000`、`setResponseAskedAt(g)`（各询问创建处打戳）、`normalize` 兜底补戳、`maybeAutoRespondTimeout(g)`（检测器 tick，幂等提交保守动作）、`renderResponseCountdown(g)`（倒计时 UI）
- Consumes: 各 `respond*` 服务函数（保守动作表 spec §2.2）

- [ ] **Step 1: 写失败测试**

`run_ai_bus_core_test.js` 追加：
1. 构造超时 pending（askedAt = now - 31s）→ `maybeAutoRespondTimeout(g)` → 保守动作 spy 被调（如 `respondWuxie(false)`）
2. 未超时（askedAt = now）→ 不提交
3. 阶段已变（pending 已清）→ 提交被拒无副作用（服务端守卫）
4. `normalize` 对无 askedAt 的响应型 pending 补戳
5. `renderResponseCountdown`：超时剩余秒数出现在返回的 banner/文案中

- [ ] **Step 2: RED → Step 3: 实现 → Step 4: GREEN**

**打戳**：在各询问型 pending 创建处（`startTrick`/`openWuxieRound`/`aoeAdvance`/`startDying`/`respondShan` 触发等）设置 `g.pending.askedAt = Date.now()`。**实现时核对**：用 `rg "g.pending=" game.js | head -50` 找所有响应型 pending 创建点，逐一补戳；`normalize` 对响应型 pending 若 `askedAt` 缺失则补 `Date.now()`（兜底，不重复打——因创建处已打）。

**检测器**：

```js
// bot-ai-bus.js 或 bot.js 启动 setInterval(1s)：
// 读 currentG，对响应型 pending 且 askedAt 超时 → 按保守动作表提交。
// 任意客户端都可检测（幂等：服务端守卫校验通过才生效；阶段已变则提交被拒）。
```

**保守动作表**：spec §2.2 逐条映射 phase → 服务函数调用。

**倒计时**：`render.js` 响应型 pending 分支显示 `⏱ Ns 后自动…`（N = ceil((askedAt + 30000 - now)/1000)）。
