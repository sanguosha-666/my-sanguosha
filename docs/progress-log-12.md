# 改动记录（第 12 段）

> 承接 `docs/progress-log-11.md`（该文件写到约 172KB，超过 150KB 的分段阈值，按 `CLAUDE.md` 开头的规则新开一段）。

- **CORE-146 手机横屏真机复查的四项跟进（自己的座位卡 / 回合徽章 / 状态横幅 / 顶部重复行）**：用户拿 844×390 附近的真机截图复查上一轮的横屏改动，对手卡 OK，但发现四个遗漏。逐条记录根因和修法：
  - **P0-1 自己的座位卡完全没被修到（根因是 CSS 特异性，不是漏写规则）**：上一轮那批覆盖全部写成 `.seat-gen-name{...}`、`.seat-hp-col{...}` 这种 (0,1,0) 的单类选择器，而基础样式里"我"的卡早就有一整套 `.seat.me .seat-gen-name{...}`(0,2,0) 的放大版覆盖（那是为 180~260px 的大卡设计的）。**(0,1,0) 永远压不过 (0,2,0)，和源码顺序无关**——所以整张"我"的卡一直停在桌面尺寸（标题 13px、势力标 18px），在 91×121 的横屏小卡上必然溢出/重叠。修法是在手机横屏块里补一整段 ⑦ `.seat.me .X` 的等价覆盖（同为 0,2,0，且写在后面），把对手卡那批改动（≥9px 字号、加粗单字势力标、装备简称、尺寸预算）逐条按"我"的卡的实际布局重做一遍，不是简单复用对手卡的数值。**这次能漏这么久的直接原因是验证脚本从头到尾只查 `#oppRow .seat`，压根没有覆盖 `#meSeat .seat`**，见下面的验证部分。
  - **P0-2「回合」徽章遮挡武将名**：`.seat-title-tags .tag.turn` 在窄标题栏里和玩家名抢位置（实测 `seat-title-name("我自己") ↔ tag turn("回合")` 重叠 8×13px）。**没有另造一个角标**——`.seat.active{border-color:var(--jade);box-shadow:0 0 0 2px var(--jade) inset}` 这条既有规则本来就已经用绿色边框表达了"当前回合"，文字标签在小卡上是纯冗余，直接 `display:none` 即可，信息没有丢失。
  - **P1-1 状态横幅"一行内两处截断"是误判，如实记录**：实测 `.banner` 的 `whiteSpace:normal` / `overflow:visible` / `scrollWidth<=clientWidth`，横幅是满宽的、放得下，**没有任何布局截断**。用户看到的省略号是 `renderResponseCountdown` 里**写死在文案里**的（`'⏱ ' + n + 's 后自动…'`）。所以不是改 CSS，而是把文案补全成 `'s 后自动替你决定'`——原文案确实没说清会替你做什么。`run_ai_timeout_test.js` 里那条正则断言同步更新。
  - **P1-2 顶部 chrome 压掉一行**：`#myGeneral`（"你的武将：…"）和座位卡上已有的武将名完全重复，手机横屏下 `display:none`，省出的高度还给座位区。
  - **额外修掉的重叠（矩阵测出来的，不在用户清单里）**：
    - **体力心 ↔ 手牌数图标**（对手卡和"我"的卡都有）：左侧 `.seat-left` 是一条绝对定位竖列（势力标 → 竖排武将名 → 体力心），右下 `.seat-equip-row` 里有手牌数图标，两者**横向落在同一条窄带上**（都在 x≈12~28）；卡片只有 121px 高时竖列一路延伸到 y≈325、图标从 y≈314 起，必然相撞。**先试过把手牌图标 `position:absolute` 挪到右侧，那是个假修复**——`.seat-bottom` 自己就是 `position:absolute` 的定位上下文，图标不是相对 `.seat` 而是相对 `.seat-bottom` 定位，直接被推到卡片外面（实测 hi-count 落在 y=361~380、而卡底是 368），重叠"消失"只是因为它飞出了卡；CSS 没法跨过 `.seat-bottom` 这层定位上下文。压缩心的排列也算过三种都不成立：①横排——武将**最大 maxHp=6**，6 颗心约 48px 宽，会撞 x=32 起的装备槽标签；②2 列 wrap——高度只能减到 22px，而体力列起点到手牌图标之间只有约 16px 余量，仍然重叠；③只显示实心不显示空心——血满时颗数不变，没解决最坏情况。**最终做法**是这个断点下体力改成"当前/上限"数字（`render.js` 的 `heartsHtml` 额外输出一个 `data-hp="3/4"` 属性，CSS 用 `::before` 读它并隐藏下面的心 div），1 行 11px，比竖排 6 心的 66px 省 4 倍纵向空间，信息完全等价。桌面/平板仍然渲染心——那些断点上没有任何规则读 `data-hp`。
    - **身份猜测标记 🔖 ↔ 装备条**（只在最窄的 667×375 / 9人局出现，卡片仅 67×90）：基础规则是 `top:58%` + `clamp(18px,16cqw,30px)`，在这么窄的卡上 `16cqw` 才算出 10.7px、被 clamp 下限顶回 18px，58% 居中后下沿落到 y≈61，而装备条顶只在 y≈43。缩到 14px 并上移到 `top:38%`，让它在最矮的一档也留在装备条上方。**这个缺陷单点样本测不到，是矩阵化验证抓出来的。**
  - **验证（用户明确要求的三条都做了）**：① `tools/verify_mobile_landscape.js` 新增 `inspectSeat`，对 `#oppRow .seat` 和 `#meSeat .seat` **两种卡**各查四项：无元素重叠（两两求叶子节点矩形交集，容差 2px 吸收 line-box 的名义交叠）、最小字号 ≥9px、装备名无截断、卡片未被视口裁切。② **重叠断言做了鉴别力实测**：临时移除体力数字化那条修复（体力恢复竖排心），断言确实变红——`对手卡 2 处重叠(8×4px / 9×10px)` + `我的卡 1 处重叠(9×10px)`，装回后全绿，证明这条断言不是"永远绿"（CLAUDE.md 规则 20）。③ 体检从单点 844×390/8人局扩成 **5 种人数(2/4/6/8/9，覆盖 MIN_PLAYERS 下限到 SEATS 上限) × 3 种横屏视口(844×390 / 667×375 / 932×430)** 的矩阵，对手一律用**颜良文丑**（4 字是全表最长武将名，竖排最容易撞下面的体力/装备）、"我"用左慈带化身（有化身行）+ 身份局（有 🔖）+ 轮到我（有 `.active`）。矩阵共 167 条断言全绿；桌面/平板断点的既有断言同时保持不变（44px 触控目标、装备全名）。全量套件 `run_all_tests.js` 137/137。
  - **顺带修掉的一条脆弱断言**：`run_discard_reveal_test.js` 里 `assert.ok(indexSource.includes('render-discard.js?v=395'))` 把 cache-bust 版本号**写死**成 395，于是**往后任何一次 cache-bust 都会让它变红**（这次就是这么红的）。它真正想守的是"这个文件带了 `?v=` 且不低于引入弃牌展示时的那一版"，不是"恰好等于 395"，改成正则取值 + `>=395` 的阈值式断言。
